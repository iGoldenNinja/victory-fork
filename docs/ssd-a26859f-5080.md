# NVIDIA `a26859f` first-room replay on the RTX 5080

The NVIDIA fork's `a26859f` revision adds mirroring for descriptor records the title copies as bytes, support for buffer views that begin partway into a copied element, video-memory reservations, and shader translation changes. The maintainer reported that the first room rendered more fully on an RTX 4070. I tested the combined main revision on an RTX 5080 16 GB with NVIDIA driver 617.14, Windows 11 Pro 25H2 build 26200.9974, Ryzen 9 5900X and 32 GB RAM. [Upstream change and test](https://github.com/fxceless/victory-fork/commit/a26859fc5f512e0db0d7522d3da821c038378ab7)

Both Series X diagnostics builds used MSVC Rust 1.98.1 and the same local archive and replay support. Both used default relay stage 2, and the title was offered 3840 × 2160. This test changes the whole upstream revision. It can quantify a change in the replay without isolating the contribution of an individual patch.

Both revisions reached player control in the prison. At the matched post-retreat angle, both rendered the walls, ceiling, fixtures, bunks and main character. The character pose differed. Stair-stepped artifacts around the shoulder remained on the new revision. Title-process PCM was present during the replay. Audio synchronization and progression past the prison remain open.

Each revision ran once. Both startup logs reported zero shader-cache hits. The same three camera pans and five movement holds ran on both builds. The first camera input matched within 23 ms after player selection, and later inputs matched within 16 ms relative to the first camera input.

The new descriptor-mirroring log reported a median 48,168 records mirrored per frame and a median 57.15 ms per frame across 257 periodic samples. The host counters can overlap in elapsed time. Both builds logged the same seven distinct pipeline sets refused with `E_INVALIDARG`, including the four previously matched compute programs. DRED logged no device removal.
